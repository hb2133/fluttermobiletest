# FLUTTER PLATFORM PROFILE (MOBILE) V2

## 1) 문서 역할
- 이 문서는 Flutter 모바일(iOS/Android) UI/UX 운영 규칙이다.
- 구조와 계층의 기본 규칙은 `ARCHITECTURE_RULES_PANEL_SECTION_FLUTTER_V1.md`, `ARCHITECTURE_RULES_PANEL_LAYER_FLUTTER_V1.md`를 따른다.
- 본 문서는 모바일 presentation 품질 기준만 추가로 고정한다.

## 2) 기본 입장
- 모바일 기본 레이아웃은 `single-pane`다.
- 기본 설계 기준은 세로 포트레이트다.
- 복잡한 분할 레이아웃은 모바일에서 억지로 유지하지 말고 단계형 화면 전환으로 푼다.
- 터치, 안전영역, 키보드 가림 대응은 필수다.

## 3) 크기 클래스
- `compact`: 0 ~ 599dp
- `medium`: 600 ~ 839dp
- `expanded`: 840dp 이상
- 모바일 프로파일에서는 `expanded`라도 데스크톱식 다중 패널을 강제하지 않는다.

## 4) 레이아웃 규칙
- 핵심 작업 흐름은 한 화면에서 한 책임만 수행하게 분해한다.
- 서브 기능은 `bottom sheet`, `dialog`, `drill-down page`로 확장한다.
- 입력 화면은 키보드 오버랩 방지와 스크롤 가능 구조를 기본으로 한다.
- `Row`/`Column`에서 고정 폭 남용을 금지한다.
- 다국어와 긴 텍스트를 고려해 줄바꿈 또는 ellipsis 전략을 명시한다.

## 5) 입력 / 상호작용 규칙
- 최소 터치 타깃은 44dp 이상을 유지한다.
- hover 전용 정보 전달을 금지한다.
- 파괴적 액션은 확인 단계를 둔다.
- 로딩이 300ms 이상 걸리면 시각적 진행 상태를 보여준다.
- 제스처는 기본 스크롤과 시스템 뒤로가기와 충돌하지 않아야 한다.

## 6) 스타일 규칙
- 색상, 간격, 반경, 폰트는 `lib/design/global_design.dart` 토큰을 사용한다.
- 컴포넌트 밀도는 터치 중심으로 유지한다.
- 본문 텍스트는 기본 가독성을 해치지 않는 크기를 유지한다.
- 모바일 전용 보정 스타일을 두더라도 전역 SSOT를 우회하지 않는다.

## 7) 성능 / 안정성 규칙
- 긴 리스트는 `ListView.builder` 등 지연 렌더링을 사용한다.
- 상태 범위를 최소화해 불필요한 rebuild를 줄인다.
- 이미지와 썸네일은 해상도에 맞는 리사이즈/캐싱 전략을 사용한다.
- 비동기 실패 시 재시도 경로를 제공한다.

## 8) 접근성 규칙
- 주요 액션에 semantics를 제공한다.
- 색상만으로 상태를 구분하지 않는다.
- 동적 글꼴 크기 변경 시 레이아웃이 깨지지 않아야 한다.
- 포커스 이동과 읽기 순서는 시각적 순서와 일치해야 한다.

## 9) 모바일 스모크 체크
- 360x800에서 핵심 화면 진입과 조작이 가능하다.
- 390x844에서 입력 폼과 키보드 상호작용이 정상 동작한다.
- 768x1024에서 정보 밀도 확장 시 레이아웃이 유지된다.
- 에러 상태와 재시도 흐름이 동작한다.

- 모바일 스모크 체크 통과
